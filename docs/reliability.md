# 読み上げ処理と障害時の動作

- サーバーごとにFIFOで処理します。合成中・再生中の1件に加え、最大32件を待機させます。満杯の場合、新しい読み上げを受け付けず警告ログを出します。
- `/skip` は現在の合成・再生を中断し、次のメッセージへ進みます。`/stop` は合成・再生と待機分を取り消してから、切断と保存状態の削除を行います。他サーバーの処理を待つことはありません。
- GCPとVOICEVOXはそれぞれ最大4件を並行合成します。HTTP接続は5秒、HTTPリクエストと合成の再試行全体は30秒でタイムアウトします。一時的な通信障害やHTTP 408/429/5xxのみ最大3回試行します。本文の不正や認証エラーで再試行を増幅させません。
- 読み上げ用の本文・表示名・辞書置換後の文字列は、UTF-8を壊さず最大500文字に制限します。GCP向けSSMLはXML特殊文字をエスケープし、生成したタグを含め最大1000バイトに収めます。ユーザーが入力したSSMLタグは実行しません。
- Redisの通信エラー、不正な型、不正なJSONは「未設定」と区別します。初期値はキーが存在しない場合のみ作成し、設定変更は比較更新で競合を検出します。Redisのユーザーには既存コマンドに加えて `EVAL` の許可が必要です。
- Discordのサーバー情報が未取得・利用不能な場合は保存状態を保持します。再接続失敗でも状態を削除せず、最大60秒の間隔で再試行します。停止時のRedis削除に失敗した場合も、実行中は後始末を再試行します（成功前のプロセス再起動では保存済み状態が復元されます）。
- `/setup` と自動参加の案内は、Botに「埋め込みリンク」権限がない場合は通常テキストでVOICEVOXクレジットを表示します。投稿自体が失敗した場合も、開始済みのTTSを維持し、`/setup` の応答では開始成功と案内の投稿失敗を表示します。エラーログには対象のサーバー・チャンネルを記録します。
- APIクライアントのDebug出力、トレース引数、HTTPエラーには認証情報や入力本文・URLを含めません。以前のバージョンで記録されたログの削除や鍵の失効・再発行は、このコード変更では行いません。

## 回帰テスト

```sh
cargo fmt --all --check
cargo clippy --locked --all-targets
cargo test --locked --all-targets
cargo test --locked --doc
cargo test --locked --lib database::database::tests -- --include-ignored
```

最後のコマンドには `redis-server` が必要です。各テストが一時ディレクトリのUnixソケットで独立したRedisを起動し、終了時に停止します。既存Redisや本番データには接続しません。APIテストはループバックの模擬HTTPサーバーと生成したMP3を使い、Discordや外部TTSへの認証情報は不要です。CIでも両方のテストを実行します。
